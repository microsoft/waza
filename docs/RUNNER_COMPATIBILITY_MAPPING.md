## Public Go API

```go
request, err := runnercompat.AdaptLocal(evalBytes, taskBytes, runnercompat.Options{
    EvalPath: evalPath,
    TaskPath: taskPath,
    RunKey: runKey,
    Selection: runnercontract.Selection{
        Shard: shard, Task: taskID, Trial: 1, Attempt: 1,
    },
    TimeoutMS: nil, // Inherit the effective local timeout; pointer asserts equality.
})
```

`AdaptLocal` returns `(*runnercontract.Request, error)`, with nil request on
every error. It uses `models.ParseCapturedEvalSpecOffline`,
`models.ParseCapturedTestCaseOffline`, `graders.ValidateConfig` and
`runnercontract.Parse`, followed by the shared pure `runnerunit.Validate`
admission path (including inline input preparation). It neither reads the supplied filenames nor creates an
engine, subprocess or runtime client. A rejecting prompt-file reader is passed
to the native task loader. Source bytes remain caller-owned and unchanged.

The library maps **captured sources**, not an entire ambient local invocation.
`EvalPath`/`TaskPath` are lexical provenance used to verify the sole configured
task filename; they are not a confinement or symlink-equivalence guarantee.
The caller must first resolve and reject unsupported local invocation state,
including effective context fixtures and flags. The CLI constructor performs bounded reads of the two named regular files and
rejects the default eval-relative fixture entry. Both callers use
`rootedfile.OpenPath`: Unix opens request `O_NONBLOCK` so a writerless FIFO,
including one substituted before open, cannot block admission. Type checking
and reading use the same owned file handle; a later path replacement is not
reopened. Ordinary native symlink resolution is retained, not confined.
Windows uses the existing helper's best-effort regular-file precheck and an
opened-handle recheck; it does not establish race-free/nonblocking opening.
This is not a filesystem snapshot/transaction, stable-content or host-isolation
guarantee. Native Linux/Windows execution remains separate evidence.

## Field mapping

| Local source | Request destination or constraint |
|---|---|
| Original eval bytes | `input.eval`, byte-for-byte, not marshaled `EvalSpec`. |
| Original task bytes | `input.task`, byte-for-byte, not marshaled `TestCase`. |
| Caller run key | `run_key`, validated by the pinned runner request schema. |
| Explicit shard | `selection.shard` and `input.shard`, equal. |
| Sole task `id` | Must equal explicit `selection.task`; selected filename must match the one literal eval-relative task entry. Absolute task entries are rejected before task capture in local compatible execution, and by the shared adapter. Ordinary native joining/selection is unchanged. |
| Trial and attempt | Exactly 1; eval trials must equal 1 and max attempts must be omitted/0/1. This adapter does not schedule a selected member of a larger batch. |
| Eval timeout + task override | Native precedence; task omitted/null inherits, present positive task value overrides. Convert seconds to milliseconds only after enforcing 1..86400 seconds. |
| Optional timeout assertion | Must equal the resolved timeout. Explicit 0 is an error, not inheritance. |
| Eval schema version | Validated by the existing captured loader, retained unchanged. Runner schema version stays independently 1.0. |
| Task field presence | Original null/empty/omitted/false declarations retained; supported native defaults are checked, unsupported fields rejected even when empty. |
| Runtime capabilities | Exactly `exact-unit`, `inline.mock-text`; optional list is empty, paid consent false. No native or terminal-result capability is invented. |
| Inline input admission | The shared runner must admit the complete request before adaptation succeeds. Prompts requiring absent workspace files are rejected, not emitted for a later runner rejection. |
| Emitted bytes | The complete JSON must fit 4,194,304 bytes. A trailing LF is added only when it fits; exact-limit JSON has no appended LF. Oversized JSON fails before any output. |
| Text checks | Both scopes and output expectations are retained, statically validated, collision checked, never flattened or dropped. |
| Historical outputs | No conversion. Shared historical aggregation and the existing writer preserve local versions, usage absence/zero, IDs and exit policy. |

See the [user matrix](RUNNER_COMPATIBILITY_MIGRATION.md) for all intentional
incompatibilities. Admission is conservative: declarations outside the adapter
allowlist fail even when ordinary native loading might ignore them.

## Production routing

`newRunnerCommand` registers the offline adapter alongside validate/run.
The root's existing runner update-check exemption covers it. Adaptation reads
only the exact sources and inspects the eval-relative default fixture entry;
it never loads project defaults or constructs a runtime.

`runCommandE` dispatches `--runner-compat` before ordinary project defaults,
telemetry, discovery and engine construction. `runLocalCompatibility` rejects
unsupported explicitly supplied flags, uses the shared project loader to reject
ambient configuration, and the shared trigger discovery to reject adjacent
trigger work. It resolves the sole literal task relative to the explicit eval,
captures exact bytes, applies `AdaptLocal`, and marshals the validated request.
Failure never falls back to native execution or writes a successful artifact.

`runnerunit.Service.RunLocal` and `RunTerminal` use the same admission, identity,
concrete mock-engine restriction, deadline, once-only engine wrapper, graded
`ExecuteInlineAttempt` and bounded shutdown. Only the result projection differs.
Local projection requires one observed trial/attempt and a recorded usage
scope; missing observations are errors, never fabricated aggregate inputs.
`EvalRunner.ProjectInlineOutcome` reuses `buildTestOutcome`, `ComputeTestStats`,
`buildOutcome` and `BuildDigest`, also used by ordinary benchmarks. No second
execution, regrading or new JSON serializer is introduced.

The CLI saves via existing `saveOutcome` and uses `TestFailureError` for failed
checks or observed execution-error attempts. The latter retain the native
`error` run and failed-task aggregate, including unavailable evidence, with
local exit 1. Typed attempt causes remain available to terminal classification;
they are never reconstructed from error text. Missing observations, startup,
lifecycle and output failures keep local exit 2. External terminal identity and
0-6 outcomes are not backfilled into historical local results. No result/API/
UI data surface changes: **no Lab dashboard change is required for #761**.

## Focused checks

With an absolute verified executable that rejects Copilot runtime launch:

```bash
ENABLE_COPILOT_TESTS=false COPILOT_CLI_PATH="$REJECTING_RUNTIME" NO_COLOR=1 \
  go test ./internal/runnercompat ./cmd/waza \
  -run 'TestAdapter|TestRunnerAdapt' -count=1
```

This selects adapter schema/presence/mapping tests, offline HTTP/ambient-config
sentinels, constructor I/O/failure tests, public root execution against the
independent historical observation, LF/CRLF controls and oracle mutation checks.
Add `TestRunnerCompat` to include opt-in local invocation rejection and failure
controls. Complete-artifact comparisons additionally retain statistics and usage
presence, removing generated eval/session IDs and timestamps, run/workspace/
grader durations and task average duration. Usage session IDs must match their
actual run before normalization; missing or changed usage data is not erased.
Repository vet, full Go tests, actual lint and
`NO_COLOR=1 make test-compat` remain required; unavailable/failed families must
be reported, not relabeled passing.

`TestRunnerAdapter` includes hard-bounded compiled CLI controls for both adapter
callers, native-versus-adapted task selection, shared prompt admission and
adapt-to-validate/run byte boundaries. Unix-only tests terminate and reap
writerless FIFO helpers and exercise parent replacement before/after opening,
regular symlink targets and opened-handle errors. They are not native Windows
execution evidence.
