**Draft - publication pending. Release date 2026-11-21.**

Waza v0.42.0 prepares the production-integration layer above the exact runner
contract and durable execution shipped in v0.40.0 and v0.41.0. It adds signed
execution provenance, component inventories, correlated telemetry, resource
budgets, isolation capability declarations, portable adapters and an
evidence-linked operator assurance package. These are bounded contracts, not a
universal deployment or security approval.

The version files are prepared for 0.42.0, but this article does not establish a
tag, published binaries, extension registry synchronization, public image,
attestations or successful release qualification. Use the
[current published standalone and azd releases](../../reference/releases/).
The download reference identifies the tag's standalone assets separately from
extension registry synchronization and native execution evidence.

### Opt-in keyless execution signing

[PR #1086](https://github.com/microsoft/waza/pull/1086) adds opt-in
`--signer sigstore-keyless` for `runner provenance generate`. It uses GitHub
Actions OIDC with public-good Fulcio and Rekor v1, and saves a Sigstore bundle
beside the unchanged DSSE statement. Keyless signing is optional and is not a
release requirement; local Ed25519 remains the default signer. Signing and
offline verification need a verifier-supplied Sigstore trusted root, and
verification also needs the exact OIDC issuer and workflow identity policy.

Not included: managed-KMS signing (still unavailable), certificate-transparency
SCT and revocation checks, Lab/API keyless verification, GitHub Enterprise
Server or custom OIDC issuers, and live public-good acceptance testing. See the
[execution provenance guide](../../guides/execution-provenance/) for
permissions, egress, trust-root acquisition and public-log disclosure.

## Qualification, CI and performance

- [#905 native platform evidence](https://github.com/microsoft/waza/issues/905)
  ([PR #1007](https://github.com/microsoft/waza/pull/1007)) separates native,
  cross-built, emulated and unavailable evidence for six targets. Native package
  smoke checks exact distributed binaries/extension packages and rejects
  architecture/digest mismatches and runtime launches. Published-package smoke
  is reported evidence, not yet a publication gate.
- [#937 immutable release retry](https://github.com/microsoft/waza/issues/937)
  ([PR #1076](https://github.com/microsoft/waza/pull/1076)) reuses an existing
  registry-sync branch only when parent/tree match the validated sync; it never
  force-pushes a different tip.
- [#981 completeness gate follow-ups](https://github.com/microsoft/waza/issues/981)
  ([PR #1003](https://github.com/microsoft/waza/pull/1003)) cover PR retargeting,
  source-bound receipt races and consolidated Docker validation.
- [#974 dashboard performance](https://github.com/microsoft/waza/issues/974)
  ([PR #1005](https://github.com/microsoft/waza/pull/1005)) restores the
  retry-disabled Playwright wall-time budget with lazy Ajv compilation and
  direct-route rendering.
- [#835 container Go caches](https://github.com/microsoft/waza/issues/835)
  ([PR #836](https://github.com/microsoft/waza/pull/836)) reuses module/build
  caches without changing the runtime contract. Related measured CI work under
  [#825](https://github.com/microsoft/waza/issues/825) balances native and
  remaining-package shards; this does not claim that the broader open issue is complete.
- [#756 qualification](https://github.com/microsoft/waza/issues/756) adds
  exact-current-main candidate qualification with binaries, OCI image archive,
  CycloneDX inventory, GitHub provenance/SBOM attestations and offline
  verification. Candidate runs publish no tag, release or registry image. The
  tag path publishes the qualified artifacts without rebuilding binaries.
  Readiness fixes add public-adapter signed-provenance verification and
  decouple native probe behavior from a hard-coded bundled CLI version
  ([#876](https://github.com/microsoft/waza/issues/876)).

## Other included source changes

[Product usage telemetry #1045](https://github.com/microsoft/waza/issues/1045)
([PR #1069](https://github.com/microsoft/waza/pull/1069)) is separate from
runner execution telemetry: allowlisted pseudonymous events are collected by
default on developer machines, never in CI or development builds, with
30-day retention. Every opt-out wins: `--no-telemetry`,
`WAZA_TELEMETRY_OPTOUT=1`, `DO_NOT_TRACK=1`, `waza telemetry disable`,
project denial and azd denial. See the [usage telemetry guide](../../guides/usage-telemetry/).

Dependency updates include Copilot Go SDK 1.0.34 and bundled CLI 1.0.112,
coordinated site/dashboard updates, and expanded native shard coverage.
Documentation/sample readiness fixes align production commands, examples,
provenance hook responsibilities and the generated assurance page with this
candidate. Historical v0.41.0 publication records and pinned downloads remain
unchanged.
