## Runner interface 1.0

The additive runner boundary supports one exact shard/task/trial/attempt through
`waza runner` or synchronous HTTP. Request bootstrap schema, runner interface,
terminal result schema and `sha256-json-v1` identity derivation are separately
versioned. Version and required-capability mismatches fail before execution;
unknown optional capabilities are recorded as unavailable. CLI and API share
negotiation and admission behavior.

- [User invocation, developer contract, schemas and capability negotiation](../../guides/runner-contract/)
- [Request schema 1.0](https://github.com/microsoft/waza/blob/main/schemas/runner-request-1.0.schema.json)
- [Terminal result schema 1.0](https://github.com/microsoft/waza/blob/main/schemas/runner-result-1.0.schema.json)
- [Exact selection, identity, terminal states and failure boundaries](https://github.com/microsoft/waza/blob/main/docs/RUNNER_CONTRACT.md)

`waza run`, `grade`, `replay` and historical schemas remain in their existing
local compatibility families. Runner logical IDs do not rewrite historical
IDs. Identical request identities do not provide exactly-once execution or
deduplication; abrupt host loss and broken output can leave no result.
