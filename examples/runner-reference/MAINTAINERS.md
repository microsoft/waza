## Publication policy (prepared, not executed)

The target package is `ghcr.io/microsoft/waza-runner-reference`. #762 acceptance
requires an actually published, anonymously pullable digest; local images alone
are insufficient. No publisher/token handling is added by this preparation.
The final publication path should use maintained OCI/Docker tools rather than a
new hand-written registry client, and must enforce:

1. A separate manually authorized workflow on canonical `microsoft/waza` main,
   with one full lowercase source SHA, verified merged ancestry, and checkout at
   that SHA. Never publish from PR merge refs, forks, `pull_request_target`,
   untrusted workflow artifacts, or mutable source input. Main ancestry is a
   prerequisite, not a substitute for review or passing current-head gates.
2. Read-only default permissions; `packages: write` only on the bounded publication
   job, with a timeout and serialized publication concurrency. Use the normal
   scoped GitHub token through maintained authentication tooling. No personal
   token, account switch, token in subprocess arguments/logs, or credential
   persistence in image layers. Build/test before registry writes.
3. Reviewed toolchain/dependency/action pins, full conformance, reproducibility
   comparison and source-revision label agreement before any push. Change the
   preparation version/description to the actual approved reference version.
4. Source tags `sha-<full-reviewed-commit>` as lookup aids, never user pins.
   Before a write, distinguish authoritative absence from network/auth failures.
   Reuse an existing matching manifest; refuse any differing existing commit tag.
   Do not overwrite or blindly retry an ambiguous push. Reconcile registry state
   first; serialized workflow concurrency alone is not a global tag lock.
5. After a successful write, read back and independently hash the OCI manifest,
   verify digest and source/config provenance, and test the digest through
   anonymous pull with an empty credential configuration. Run the same full
   conformance on that pulled digest in the supported clean environment.
6. Emit the public digest receipt **only after** all verification succeeds.
   An unsuccessful publication/public-access check may leave registry content
   but must never emit a confirmed success pin. Reconcile before another write.

If GHCR organization/package policy prevents public access, report that exact
blocker. Do not weaken the criterion, make access changes implicitly, or advertise
an authenticated-only digest as publicly pullable.
